# @chatwoot-next/auth

Authentication primitives for the Chatwoot Next.js app: an Auth.js v5 config wired up with a Devise bcrypt credentials verifier, a `devise-token_auth`-compatible token validator, TOTP + backup-code helpers, and a multi-tenant SAML provider backed by `account_saml_settings`. The package's job during the Rails-to-Next.js cutover is bidirectional session compatibility: Auth.js issues JWT sessions but **also** writes a row into the `users.tokens` JSON column in the exact shape `devise-token_auth` expects (per-client bcrypt-hashed token + expiry), so the existing Rails strategy accepts sessions minted by Next.js. In the reverse direction, Rails-issued sessions arriving with the `access-token` / `client` / `uid` / `expiry` header tuple are validated by `validateDeviseToken`, letting Next.js route handlers honor logins still happening through the Rails UI until the migration completes.
